hai-proof

Harness for AI Plugin Rigorous Outcome and Overhead Framework. It checks whether a change to Claude Code's harness (a CLAUDE.md, skills, hooks, subagents, MCP servers, a plugin) actually changes what the agent gets done, how long it takes and what it costs.

People add skills, hooks and plugins to Claude Code because they make it "feel better". hai-proof measures that. It runs plain Claude Code (the control) and Claude Code with one modification bundle (the treatment) through the same coding tasks, in pairs of containers started at the same moment, and reports:

  1. Success: do hidden tests, which the agent never sees, pass afterwards?
  2. Wall-clock time, measured inside the container.
  3. Tokens and cost for the whole agent tree, subagents included.

It is a smoke test built to catch large differences cheaply, not a leaderboard. The working hypothesis the treatment has to beat is that both arms solve the tasks and the treatment costs more.

Quick start

uv sync
cp hai-proof.example.toml hai-proof.toml          # set model and default_host
cp .env.example .env                              # one of ANTHROPIC_API_KEY / CLAUDE_CODE_OAUTH_TOKEN

uv run hai-proof hosts check <alias>              # preflight the Docker host
for t in tasks/*/; do uv run hai-proof build-task "$t"; done
uv run hai-proof validate-task --host <alias>     # no API spend

uv run hai-proof run --host <alias> --treatment <name> --mode lightning --dry-run
uv run hai-proof run --host <alias> --treatment <name> --mode lightning

Or open the repository in Claude Code and ask in plain words ("package my setup as a treatment", "evaluate it against plain Claude Code"); the project skills take it from there. Real runs spend API credit or subscription usage, so always dry-run first.
