We moved our API gateway's request routing to this library because it claims strict RFC 9535 compliance, but this release is far from compliant, mostly around filter expressions and function extensions. We have a large set of conformance checks of our own derived from the RFC. With this version about 130 of roughly 700 fail. The RFC and the I-Regexp RFC it references are in `docs/rfc/`.

Rough breakdown of what fails (examples, not an exhaustive list):

- **Filters, about 55 failures.** Existence tests depend on the *value* instead of whether the node exists: `$[?@.a]` drops objects where `a` is `null`, `false`, `0` or `""`, and `$[?@]` drops falsy array items. Comparisons don't follow the RFC's type rules: `$[?@.a==1]` also matches `"a": true`, ordering comparisons (`<`, `<=` and so on) between arrays or between booleans return results they shouldn't, and comparisons against missing members misbehave.
- **Function extensions, about 50 failures.** `length(@.a)` returns 1 for any existing `a` instead of the length of its value. `match()`/`search()` on a query argument never match. Calls that the RFC says are not well-typed parse without error, e.g. `$[?count(1)>2]`, `$[?count(@..*)]` (result not compared), `$[?length(@.*)<3]` (non-singular query as a value argument) and `$[?match(@.a, 'x')==true]`. Patterns that are not valid I-Regexp are accepted, and `.` matches characters it shouldn't.
- **Whitespace in function calls, about 15 failures.** Probably the same function-argument problem. For example, `$[?search(@ ,'[a-z]+')]` and `$[?search(@,\n'[a-z]+')]` select nothing from `["foo", "123"]`.
- **Normalized paths, about 12 failures.** `node.path()` and `nodes.paths()` don't escape member names properly. A key containing a backslash, newline, tab or other control character comes out raw instead of in the RFC's normalized-path form, e.g. `$['\\']` or `$['\n']`.

Index, slice and the basic selectors all look fine, as does everything not involving filters, function extensions or path output. Please fix the library so it follows RFC 9535 on all of the above, both for `find()`/`finditer()` (nodes with paths) and `findall()` (values only), and make invalid queries raise the same error types the library already uses for ill-typed expressions. Keep the existing tests passing, and add tests for what you fix.
