This is how I want request lineage to work:

- Every `Request` has an `id`, an integer, unique for each request object that gets created, including across separate crawler processes (the exact scheme is up to you, as long as two requests never share one). It is read-only: assigning to `request.id` raises `AttributeError`.
- `Request` also has a `parent_id`, which is `None` by default. It is a keyword argument of the constructor, `Request(url, parent_id=1)`, and an ordinary attribute I can read and set.
- `request.copy()` and `request.replace(...)` return a request with a new `id`, and its `parent_id` is the `id` of the request it was made from (not that request's own `parent_id`). That way a retry or a redirect points back at the request that was retried or redirected. If I pass `parent_id` explicitly to `replace`, that value wins, including `parent_id=None`, which clears it.
- `Response.follow(...)` and `Response.follow_all(...)` set `parent_id` to the `id` of the response's request. If the response has no request, `parent_id` is `None`.
- When a spider callback yields requests, the scraper sets `parent_id` on each request that does not have one yet to the `id` of the request that the response belongs to. The same goes for an errback, using the request that failed. This works the same whether the callback is a normal generator or an async generator, and for a callback that returns a list or an iterable. A request that already has a `parent_id` is left alone; the scraper never overwrites an explicit value. A request yielded with `parent_id=None` set explicitly is the same as not set, so it gets filled in. Items and anything else the callback yields are passed through untouched.
- Both `id` and `parent_id` survive `request.to_dict()` and `request_from_dict(...)`: the rebuilt request has the same `id` and `parent_id` as the original. A dict that has no `id` (made by older code) still loads, and the rebuilt request gets a fresh `id` of its own.
- The same applies to every `Request` subclass (`FormRequest`, `JsonRequest`, `XmlRpcRequest`, custom ones).
