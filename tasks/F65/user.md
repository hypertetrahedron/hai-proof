I want every device to record what caused its latest update, in `Device.last_update`, so my callbacks can tell which telegram or which application action changed a state.

This is how I want it to behave:

- `Device.last_update` is a `DeviceUpdate` (exported from `xknx.devices`): an immutable value with two fields, `telegram` (the `Telegram` that caused the update, or `None`) and `context` (an application-defined object, or `None`). Two `DeviceUpdate`s compare equal when both fields are equal. Before a device has had any update, `last_update` is `DeviceUpdate()`, i.e. both fields `None`.
- It is set before the device-updated callbacks run, so a callback reads the cause of the update it is being called for, and it stays available after the callbacks return, until the next update replaces it. The callback signature does not change: it stays `callback(device)`, with no extra argument. This also applies to the callback registered on `XKNX(device_updated_cb=...)`.
- When a processed telegram caused the update, `telegram` is that telegram, incoming or outgoing, and `context` is `telegram.context`.
- `telegram_context(obj)` is a context manager. Outgoing telegrams created inside the `with` block carry `obj` in `Telegram.context`. An explicit `Telegram(..., context=x)` wins over the active one, a nested `telegram_context(None)` really clears it, and leaving a block restores the outer value. Outside any block it is `None`. Tasks started inside the block inherit it, which matters for the next point.
- Incoming telegrams never pick up the context of whatever task receives them, even if the receiving code happens to run inside a `telegram_context` block. They only carry a context if one is set on them explicitly, for example `Telegram(..., direction=TelegramDirection.INCOMING, context=x)` by a telegram-received callback. Handing an incoming frame to `xknx.cemi_handler.handle_cemi_frame` inside a `telegram_context(obj)` block must give a queued incoming telegram with `context is None`.
- An update that no telegram caused, for example `switch.switch.update_value(True)` on a remote value, has `telegram` `None` and `context` equal to the active `telegram_context`, or `None` if there is none, so `DeviceUpdate()` when nothing is active.
- Updates that a device runs later from a task keep the cause of what started the task:
  - Cover travel: the periodic position updates while a cover travels all report the telegram that started the travel, including its context. If the application started the travel with `set_position()` inside `telegram_context(obj)`, the immediate update, every periodic update and the final one at the stop all report `DeviceUpdate(context=obj)` (no telegram), and the stop telegram that the auto-stop sends, from a task `set_position()` started, carries `obj` too, just like the move telegrams.
  - Light with individual colour channels (red, green, blue sent as separate telegrams): the updates are debounced into one callback. It is attributed to the last telegram received in the debounce window, not the first.
  - Binary sensor with `context_timeout`: when the timeout expires and the counter update is made, it is attributed to the telegram that was counted, so both callbacks report `DeviceUpdate(telegram=that telegram)`.
- The cause must not leak into work scheduled from a device callback. While the callbacks run, the "currently processed telegram" is cleared, so something an application schedules from inside a callback (for example an automation started with `call_soon`) does not inherit the telegram that triggered the callback. If that automation then uses `telegram_context("automation")` and moves a cover, the cover's updates are `DeviceUpdate(context="automation")`, the outgoing telegram carries "automation", and the travel updates keep that, not the wall switch's telegram or its context. If the automation uses no `telegram_context`, the updates are plain `DeviceUpdate(context=None)` and the outgoing telegram's context is `None`. The cause is still readable inside the callback itself.
- `Telegram.context` is excluded from equality and from `repr`: two telegrams that differ only in context are equal, and `repr` does not show it.
