Here is how I want a config `null` (JSON `null`, or `None` in a `Dict` source) to behave:

- If the parameter's type does not allow `None`, a config `null` is an error: a `CoercionError` (from `app(..., exit_on_error=False)`). That covers `x: int`, `x: str`, a `null` value inside a `dict[str, int]` or `dict[str, str]` (`{"k": null}`), a `null` element of a `list[int]`, and a `null` for a dataclass field `n: int`.
- If the type allows `None`, the `null` binds `None`. That covers `int | None`, `Any | None`, plain `Any`, `Any | int`, a `dict[str, int | None]` value, a `dict[str, Any]` value, `list[int | None]` and `list[Any]` elements (`[1, null]` stays `[1, None]`), and `tuple[Any, ...]` (`[null]` gives `(None,)`). `Literal[None]`, or a `Literal` that includes `None`, also allows it, alone or as a union member.
- An unannotated parameter (`def main(x)`) takes the `null` as `None`, like `Any`, and so does a dataclass field annotated `Any`.
- But a parameter is typed by its default when the annotation says nothing: unannotated `x=0` and `x: Any = 5` count as `int`, so a `null` for them is a `CoercionError`, like for `x: int = 5`. A default of `5` does not make `null` acceptable.
- The one exception is a `None` default: for `x: int = None` (and a dataclass field `n: int = None`), a config `null` binds the `None` default, the same as if the key were absent.
- A `null` for a class that does not allow `None`, whether a dataclass, or a pydantic model, or a `dict[str, Cls]` value or `list[Cls]` element, is an error instead of building the class from an empty value or reporting each of its fields as missing. For a pydantic model the error says `unable to convert "null"`; for the others a cyclopts error is enough. If the class is optional (`Cls | None`, `Cls | Literal[None]`, `Literal["x", None]` unions, also as a dict value) the `null` binds `None`.
- A keyed `null` inside an optional dict, `x: dict[str, int] | None = None` with config `{"k": null}` or `{"a": 1, "k": null}`, is an error, because the value type `int` can't be `None`; it must not be read as "the whole dict is `None`". If the value type allows it (`dict[str, int | None] | None`), `{"a": 1, "k": null}` binds `{"a": 1, "k": None}`.
- An `Annotated[Any, Parameter(validator=...)]` dict value that receives a `null` still goes through its validator, which sees `None`.
